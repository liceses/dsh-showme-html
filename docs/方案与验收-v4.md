## 一、最终定位

经历过四次收窄，最后落在这里：

> **这个插件就是三件事：① 一个快捷入口 ② 让 AI 懂怎么写 ③ 反馈能快回来。**
>
> 页面长什么样——版式、结构、配色、是不是"汇报 + 点名"两段——**全部不规定**，每次由 AI 决定。

定位演进的四步（保留下来是为了记住"为什么不是别的"）：

| 轮次 | 当时以为要做什么 | 为什么被否 |
|---|---|---|
| v0.1 | 通用 HTML 展示器（替代 Markdown 汇报） | 与 DSH 自带的右侧栏文档预览高度重叠，价值不清 |
| v1.0 | 汇报页 + 固定模板三套 | 模板会把形式钉死，质量靠模板不靠 AI 判断 |
| v3 | 指认器（用户点选拿到 AI 给的名字） | 方向对了，但仍想固定"汇报 + 点名"两段结构 |
| **v4** | **快捷入口 + skill 定功能不定形式 + 反馈回路** | — |

用户原话（这是本项目的需求源头）：

> "我有很多 AI 生成的图片或者 AI 生成的网页组件，我没办法一个一个准确地叫出他们的名字，
> 他们的名字是 AI 可以给出的。在这个静态网页里，我希望我选择哪一个组件就可以得到组件的名称
> 用来和 AI 交流，还可以表达我的意见，比如说同意，或者要某个组件的风格。"

> "不用固定那个页面的形式，约束过多反而会影响 AI 发挥。把关键的功能点做成 skill 就好了。"

## 四、镜像读路由：本方案的技术核心

```
GET /api/showme/raw/<sessionId>/<工作区相对路径>
```

**为什么不能读成 Blob**：用户要展示的第一类东西就是"AI 生成的图片"。若把页面读成 Blob 塞进
iframe，页面里 `<img src="stills/a.png">` 这类相对引用**全部失效**，AI 只能把图片 base64 内联进
HTML——又贵又笨。

**镜像路由怎么解决**：页面是从"它自己在工作区里的那个目录"被服务的，于是相对路径按浏览器原生的
文件系统语义解析，AI 写页面时不需要知道任何 URL 前缀。同一个地址也就是「在浏览器打开原文件」。

### 安全模型（两层，刻意不同）

| | 卡片内（iframe） | 真浏览器新标签页 |
|---|---|---|
| 生效 sandbox | iframe 属性 **∩** 响应头 CSP | 只有响应头 CSP |
| 脚本 | ✅ | ✅ |
| 表单 / 下载 / `alert` / 弹窗 | ❌ | ✅ |
| 能碰到 DSH 应用本身 | ❌（不透明源） | ❌（CSP `sandbox` 强制不透明源） |

响应头是 `Content-Security-Policy: sandbox allow-scripts allow-forms allow-modals allow-downloads allow-popups`。
**这一条是"能在浏览器打开原文件"之所以安全的原因**：即使有人在标签页里直接打开这个地址，
文档也被强制放进不透明源，拿不到应用数据。而卡片额外叠了 `sandbox="allow-scripts …"`，
两层取交集 → **卡片是安全模式，浏览器是功能完整的逃生门**。

其余围栏：回环围栏（仅 `127.0.0.1`/`::1` + 同源）、工作区根 + realpath 双重校验
（`..`、`%2f`、`%5c`、指向工作区外的软链接一律 403）、扩展名白名单（否则 415）、
`nosniff` + `no-referrer` + `no-store`。

### 六之补二 · `sessions.get(id)` 的返回形状（本次真 bug）

`ctx.sessions.get(id)` 返回的是 `Session`，它暴露 **`header.cwd`**，**没有 `meta`**：

```ts
export class Session {
  readonly header: SessionHeader   // ← SessionHeader.cwd?: string
  get id(): SessionId
  ...
}
export interface SessionHeader {
  readonly version: typeof SESSION_FORMAT_VERSION
  readonly id: SessionId
  readonly createdAt: number
  readonly cwd?: string          // ← 工作区根在这里
  ...
}
```

写成 `get(id)?.meta?.cwd` 会永远拿到 `undefined`，然后掉到"全局兜底根"上去搜错目录。
`sessionQuery.readSession()` 返回 `SessionLogSnapshot`（克隆的 header + 完整事件日志），也不是 `meta`。

**同一个 profile 里的 `dsh-text-drop` 正是这么写的**（`src/index.ts` 的 `sessions.get(id)?.meta?.cwd`），
所以它那条 save 路由大概率一直在写错目录——有需要的话值得顺手看一眼。

本插件已改为 `header.cwd → meta.cwd → 裸 cwd` 依次尝试，并且**去掉了全局兜底**：
会话认不出来就 404，否则一个伪造的 sessionId 就能读全局根下的文件。

### 六之补三 · 路由上下文里拿不到 `sessions` / `sessionQuery`

改完上面那条、重启验证，**仍然** `unknown session`。而工具本身是成功的
（`exec.agent.session.header.cwd` 有值），所以问题不在会话数据，在**路由所在的插件上下文**：
`ctx.get('sessions')` / `ctx.get('sessionQuery')` 取不到（Inspect 也把这两个标注为
`access.optional` + `requiresUndefinedCheck`），于是路由对任何会话都解析不出 cwd。

**最终设计：让权威来源绕过服务。**

1. **工具执行时把 `会话 → 工作区根` 记进模块级 Map**。`show_html` 在 agent 作用域里跑，
   `exec.agent.session.header.cwd` 一定有值（没有就当次调用直接失败）。
2. **工具顺带把地址算好下发**：`execute` 返回 `url = /api/showme/raw/<sid>/<路径>`，
   经 `presentationMeta` 落进 `meta`，卡片**优先用 `meta.url`**。
   这样连"客户端的 `sessionId` 是否等于宿主 `session.id`"都不再是前提——只剩一条依赖：
   路由认识那个会话，而它刚被工具写进去。
3. 服务查询保留为兜底；认不出来时错误信息回报**具体哪个服务缺了**
   （`sessions=absent` / `sessionQuery=threw(...)`），下次不用猜。
4. 围栏不放宽：没被 `show_html` 展示过的会话照样 404；记录来源同样受工作区根约束。

对应断言在 `test/route.test.mjs` 的「服务缺失时靠工具记录兜底」一节：
未记录 + 服务缺失 → 404 且给出诊断；工具跑一次 → 同一地址立刻 200；
`%2e%2e%2f` 越界仍 403；没展示过的会话仍 404。

> 注意这不是"唯一来源"：服务查询仍在其后兜底，所以**重启不会让老卡片失效**——
> 只是当某个服务在该上下文里缺失时，工具记录那条路还能顶上。

### 六之补四 · 同一个错误犯了两次：拿 `Sec-Fetch-Site` 做围栏判断（**最贵的一课**）

展示页运行在 `sandbox` 的**不透明源**里。它发起的**一切**请求——加载自己的图片、样式、
嵌套页、页内 `<a href>` 跳转、以及它自己的 `fetch`——都被浏览器标成
`Sec-Fetch-Site: cross-site`，`Origin` 还是字面量 `"null"`（`new URL('null')` 直接抛）。
只有**页面文档本身**是父页面发起的导航（`same-origin`），所以 HTML 进得来。

于是任何拿 `Sec-Fetch-Site` 做判断的围栏，都会一块一块地咬死自己的页面。两次现场：

| 围栏写法 | 现场 | 后果 |
|---|---|---|
| `if (site === 'cross-site') return false` | **"卡片出来了，数据流图裂了"** | 页面里所有相对引用全灭（图片/样式/嵌套页） |
| 只拒 `site === 'cross-site' && dest === 'document'` | **"点图片到达错误页：forbidden: loopback-only"** | 页内 `<a href="shot-f3.html">` 跳转、打开图片、多页汇报全被拦死 |

**最终判断（`isLoopbackRequest`）——`Sec-Fetch-Site` 一个字都不看：**

```js
// 1) 只接受回环 remoteAddress
// 2) Host 必须是回环（挡 DNS rebinding 那类把戏）
// 3) Origin：缺失或 "null" 放行；否则必须与本机 Host 相同
```

`Origin` 那条就够了，因为真实跨站请求带的是 `https://evil.example`。
`Sec-Fetch-Site` 在这里**完全冗余**——真正撑住路由的是
**只收回环地址** + **一个 CORS 头都不发**（跨站方发起了也只会拿到不透明响应，
读不到内容，也就拿不走工作区文件）。

回归断言（`test/route.test.mjs` 里三条各自标注了现场）：
`cross-site + dest=image` → 200、`dest=iframe` → 200、`dest=document` → 200、
`Origin: null` → 200、**带真实 `Origin` 的跨站 fetch / 文档导航 → 403**、非回环 Host → 403。

> **教训一**：安全围栏要用**真实流量**验，不能只靠"看起来标准"。这个写法在浏览器安全文章里
> 到处都是，但在**沙箱 iframe 服务自己页面**这个场景下，它从头到尾都是错的。
> **教训二**：用户的现场描述是最高密度的线索。"数据流图裂了"把问题精确锁定到子资源请求，
> "点图片到达错误页"又把范围缩到文档导航——两次都比"页面打不开"有用得多。

## 六之补五 · 预设样式层（增补）

**需求**：让 AI 写出来的页面更好看。参考 [StyleKit](https://www.stylekit.top/zh/styles)（148 种风格）。

**关键技术冲突**（决定了这个需求只能这么做）：

| StyleKit 给 | 我们的场景 | 结论 |
|---|---|---|
| `tokens` = Tailwind 类名 | 单文件静态 HTML，无构建无 CDN | ❌ 直接抄要引 Tailwind |
| `components` = React + Tailwind JSX | 纯 HTML | ❌ 用不上 |
| `colors` = 原始 hex | — | ✅ 直接用 |
| `doList` / `dontList` / `philosophy` | — | ✅ 可翻译成原生 CSS |
| `globalCss` | — | ⚠️ 它自己承认偶有与 `dontList` 矛盾的条目，**不能照抄** |

→ **结论：把 StyleKit 当「风格词表 + 约束清单」，预设手写成原生 CSS。**
（实测样本：neo-brutalist 的 `dontList` 禁渐变，它的 `globalCss` 里却定义了渐变类。）

**核心设计：四套预设吃同一套语义标记。**
这不是版式约束，是**可换皮肤的前提**——同一份标记换皮肤一个字都不改，
也才让"可切换预览器"成为可能。标记清单见 `skill/showme-report/SKILL.md` §2.1。

**四套预设**（`styles/`）：`soft` 柔和现代（默认）· `swiss` 瑞士国际主义 ·
`brutal` 新野兽派 · `blueprint` 蓝图。每套 = 设计令牌 + 全部共用标记 + do/don't 说明。
令牌驱动，所以 `soft` / `swiss` 的明暗切换只是重声明一次 `:root`。

**四个定下来的选择（用户拍的）**：

1. **定位**：可选菜单 + 一个默认推荐（不指定就用 `soft`）——保住了"不锁形式"的原则。
2. **落地**：页面外链同目录 CSS（`<link href="presets/soft.css">`），不内联。
   省 token，且改一次预设所有页面一起变。
3. **配置面**：**不做设置页**——决定外观的是模型不是插件运行时，纯前端设置传不到模型那里
   就是假开关。改用 `presets/index.json` 里的一行 `default`。
4. **挑样式的方式**：做一页**可切换预览器**当配置界面（用 `show_html` 推给用户看）。

**宿主行为**：`show_html` 执行时把 `styles/` 里的预设落到 `<工作区>/.dsh/showme/presets/`，
**create-only**（已存在的不覆盖，用户可以自己改）。由宿主做而不是让模型 `write`：
前者零 token，后者每套要抄几千字。

**产物**：`.dsh/showme/preset-gallery.html` —— 顶部按钮 / 快捷键 1–4 换皮肤，
同一份内容四种读法；每套可"设为默认"，用 skill 的一行一条格式回执给 AI。

## 七、关键工程决策与其理由

### 7.1 放弃 TypeScript + tsdown，改用零构建纯 JS

计划里写的是"骨架抄 dsh-text-drop"，实际改成手写 `lib/*.js`，理由三条：

1. **依赖版本解析不通**：text-drop 的 devDeps 写 `@deepseek-ai/*@^0.1.0-rc.7`，
   而本机装的是 `0.1.5-rc.1`。semver 规定预发布版本只在"同 major.minor.patch 元组"的
   范围内可满足，`0.1.5-rc.1` **不满足** `^0.1.0-rc.7`。抄过来的骨架装不上。
2. **移除全部网络与构建依赖**：没有 `dependencies`/`devDependencies`/`peerDependencies`，
   `pnpm add link:` 退化成一次纯符号链接（实测 413ms）。
3. 同 profile 里的 `dsh-workspace-tree` 就是零构建形态，**先例已证明可行**。

### 7.2 宿主半区不 import 任何 harness 包

以 `link:` 安装时插件位于工作区外，Node 从**真实路径**向上找不到 profile 的 `node_modules`，
外部 import 解析不了。同 profile 里 `dsh-text-drop` / `dsh-workspace-tree` 的宿主半区同样
只 import node 内置模块——这正是它们能工作的原因。

因此 `show_html` 按 `ToolDefinition` 契约**手写**。契约（已从 `dsh-tools` 源码核实）：

- 继承 `ToolSchema` = `{ name, description, parameters }`，`parameters` 是**已编译好的 JSON Schema**
  （`defineTool` 内部就是 `parameterSchemaSpecToJsonSchema` 的结果）
- `output: { schema, render(args, value), presentationMeta?(args, value) }`
- `execute(args, exec): Promise<unknown>`
- `ctx.tools.register()` 只校验 `output.schema`（`assertSupportedJsonSchema`），
  **不校验 `parameters`**，也不做参数校验 → 代价是校验得自己写在 `execute` 里，做了。

### 7.3 "填入输入框"是可行的，而且不用起服务器

客户端服务目录（layout / locale / sessions / slots / theme / timer / uiWorkspace / workspaces）
里**没有**写输入框的服务，一度以为这条路不通。但槽位契约里有：

- `tool.call.toolview` 的标准 props 直接带 `sessionId` 与 `inputActions: InputActions`
  （`setDraft(text)`）
- `conversation.input.left` 座位的 owner props 带 `input.draft` 与 `inputActions`

于是"点一下填进输入框"是**浏览器内的本地操作**，不需要服务器、不需要经过 AI。
实现上两条都用了：镜像座位拿当前草稿（**追加而不是覆盖**），卡片的 `inputActions` 做兜底。

## 八、已知限制（认账）

| # | 限制 | 说明 |
|---|---|---|
| L1 | 不缓存 | 每次刷新重读文件（故意的：页面会被反复改） |
| L2 | 无范围请求 | 大视频会整个读进内存再发 |
| L3 | 无文件监听 | 改完要按「刷新」；自动刷新是后续里程碑 |
| L4 | 卡片内能力受限 | 表单/下载/`alert` 被拦；需要就用「浏览器打开」 |
| L5 | 不支持 `file://` 链接 | 浏览器禁止 http 页面跳 `file://`，所以走 HTTP 路由 |
| L6 | 单页 8 MiB / 反馈 256 KiB | 超限拒绝而非截断 |
| L7 | 手写 ToolDefinition 无自动参数校验 | 已在 `execute` 里显式补齐 |
| L8 | 客户端半区必须单文件 | 模块表只解答平台模块，本包内部相对 require 不走加载器 |
