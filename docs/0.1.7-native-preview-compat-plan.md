# 与 0.1.7 原生文档预览共存 —— 兼容计划（showme-html）

> 状态：**计划**（尚未实施）。前提：插件已通过 DSH 0.1.7-rc.2 移植，保留在 web profile。
> 决定来源：2026-09-26「showme html 保留并计划兼容原生预览」。

## 0. 为什么需要这份计划

DSH 0.1.7 的 web 组合里，下面这些**原生行已挂载**（`dsh --profile web --dump-config` 逐条核对过）：

| 原生 entry | 包 | 与本插件的关系 |
|---|---|---|
| `ui-sidebar-documentpreview` | `@deepseek-ai/dsh-client-ui-sidebar-documentpreview` | 右侧栏现在**原生就能预览 html / code / image / pdf / office / excel / markdown / text**，还有按目录自动刷新 |
| `dsh-client-ui-deliverables` | 同名 | 交付物卡片（presentation 表面） |
| `dsh-tool-present` / `dsh-agent-tool-presentation` | 同名 | 交付物呈现链路 |

本插件的价值**从来不是渲染**（它自己的 `docs/需求与方案-v1.0.md` 第 30 行就写明：
「DSH 已经能在右侧栏预览 HTML 文件……所以本插件的价值不在渲染，而在这三条」）。
它的独有价值是**反馈闭环**：页面上的「点名 + 表态」→ 一行回执 → 填入输入框 → 回到 agent。

所以目标不是"取代原生预览"，而是：**让原生预览成为这条链路的一部分，且互不抢占地盘。**

## 1. 现状（已核实，2026-09-26）

| 面 | 现状 |
|---|---|
| 宿主 | `show_html` 工具（手写定义，非 `defineTool`）+ 一条 `ctx.webServer.register` 路由，带工作区围栏（越界 403 / 不存在 404 / 未登记类型 415） |
| 客户端 | 三个座位：`tool.call.toolview`（keyed by `show_html`，对话内卡片）、`shell.overlay`（全屏）、`conversation.input.left`（输入框捕获） |
| 与原生预览的关系 | **目前零冲突**：本插件没有注册任何 `documentPreview`，也没有接管 `html` 扩展名；它只在自己的卡片里用 iframe 渲染自己的路由 |
| 文档里那条更宽的接口 | 设计文档提到 `ctx.sidebarRightTabs.register(...)` —— **在 0.1.7 已发布的 `.d.ts` 里按该名字找不到**（见下节），不要照抄 |

## 2. 0.1.7 已核实的扩展点（照这些写，不要照旧文档猜）

来自 `@deepseek-ai/dsh-client-ui-sidebar-documentpreview@0.1.7-rc.2` 的类型声明：

```ts
// lib/types/client/index.d.ts
declare module '@deepseek-ai/cordis' {
  interface Context {
    documentPreviews: DocumentPreviewRegistry      // ← 服务名，0.1.7 仍在
  }
}

// lib/types/client/registry.d.ts
interface DocumentPreviewDefinition {
  readonly extensions: readonly string[]           // 声明的后缀，支持 tar.gz 这类复合后缀
  readonly binaryExtensions?: readonly string[]    // 必须是 extensions 的子集，否则 register 抛错
  readonly priority?: 'builtin' | 'extension'      // ← 0.1.7 是二值枚举，不是数字
  // …（title / loading / wrap 等，实施前逐个核对）
}
register(definition: DocumentPreviewDefinition): () => void
```

keyed 槽位（来自 `contract.d.ts`）：
`sidebar.right.tab.document`、`sidebar.right.tab.document.actions`、
`sidebar.right.tab.document.action`、`sidebar.right.tab.document.unpreviewable`。

> ⚠️ **实施前必须再核一次**：`sidebarRightTabs` 这个名字在 `profiles/node_modules/@deepseek-ai/**/*.d.ts`
> 里搜不到；若要注册"新的 tab 类型"而不是"某个后缀的渲染器"，
> 先读 `@deepseek-ai/dsh-client-ui-sidebar-right` 的 client contract 确认现在叫什么
> （参考做法：`ctx.inject(['sidebarRightTabs'], cb)` 驱动注册，等**服务**而不是等槽位声明）。

## 3. 计划（四个阶段，每阶段独立可交付）

### P0 —— 零风险的共存加固（半天）

不改任何渲染行为，只把边界钉住：

1. **明确不认领全局 `html` 后缀**。不加 `documentPreviews.register({extensions:['html']})`，
   保持原生 `builtin` 预览是 `.html` 的默认归宿。
2. 在客户端加一条**启动自检**：读取 `ctx.documentPreviews` 的注册表快照，
   如果发现本插件的 id 出现在 `.html` 的候选里（说明有人误加了认领），就打一条明确警告。
3. 把这条边界写进 `test/client-bundle.test.mjs` 的断言（沿用本仓已有的静态门禁风格）。

**验收**：`node --test test/*.mjs` 全绿；原生 `.html` 预览不受影响。

### P1 —— 卡片头部新增「用原生预览打开」（1 天）

1. 卡片头部现已有 `刷新 / 全屏 / 浏览器打开`，新增第四个动作 **`原生预览`**。
2. 实现走**原生右栏**而不是自绘：拿当前会话 id + 工作区相对路径，调用右栏的 open-resource 入口
   （原生 `files` / documentpreview 的地址协议是 `dsh-resource://file/**`，
   实施时以 `@deepseek-ai/dsh-client-ui-sidebar-right` 的 contract 为准）。
3. 失败兜底：目标类型此刻不可用时 `window.open(url, '_blank', 'noopener,noreferrer')`，
   不要静默什么都不做（0.1.7 的一个已知坑：`service.openTab` 对**未注册**类型会静默 return）。

**验收**：点「原生预览」后页面出现在右侧栏原生 tab 里，且**本插件的反馈条仍然可用**
（这是关键 —— 别为了原生预览把反馈闭环丢掉）。

### P2 —— 反馈闭环与原生交付物对齐（1–2 天）

0.1.7 引入了 `dsh-client-ui-deliverables` + `dsh-agent-tool-presentation` 这条原生交付物链路。
本插件的卡片应当：

1. 让**呈现元数据**（标题 / 体积 / 资源地址）走与原生一致的 presentation 契约，
   而不是自造一套 —— 本仓 `lib/index.js` 里已经有 `output.presentationMeta({ bytes, url })`，
   实施时对照 `@deepseek-ai/dsh-tools/presentation` 的类型确认字段名。
2. 保留**自己的**卡片体（因为反馈条是独有的），但在视觉上不重复原生 deliverables 已有的信息层级。

**验收**：同一条 `show_html` 结果在对话里只有一张卡片；原生 deliverables 不会重复渲染同一份产物。

### P3 —— 让原生预览也能吃到反馈闭环（可选，按需）

如果 P1 之后你希望"在原生预览里也能点名表态"：

- 通过 `documentPreviews.register({ extensions: ['html','htm'], priority: 'extension', ... })`
  注册一个**本插件专用**的渲染器（注意 `priority: 'extension'` 只覆盖显式认领的场景），
  并在里面复用现有的反馈注入脚本。
- **必须**同时确认：普通 `.html` 打开仍然走原生 `builtin`（用 P0 的自检守护）。

这一阶段是收益/风险比最低的，**默认不做**；只有当你确实经常需要"在右栏里边看边表态"才做。

## 4. 不做什么（明确的负面清单）

- ❌ 不认领 `png/jpg/pdf/xlsx/docx/…` —— 原生 `ui-sidebar-documentpreview` 已经全部覆盖，
  认领只会把用户从更好的原生视图里赶走。
- ❌ 不再依赖 `ctx.sidebarRightTabs`（除非 P2 实施时确认了它的现名）。
- ❌ 不为了"兼容原生"把自绘全屏（`shell.overlay`）删掉 —— 原生预览是**右栏**，全屏是**画面内**，
  两者是不同场景，保留。
- ❌ 不改宿主那条带围栏的路由（403/404/415 的边界已经过测试，见 `test/route.test.mjs`）。

## 5. 与本次移植的关系

本插件本轮只做了 0.1.7 的**必需**适配（`dsh.manifestVersion`、`engines.dsh`、
`dsh.client.inject` 去掉已消失的 `dsh-client-runtime`、重建 `lib/`），
业务逻辑一行未改。上面 P0–P3 是**新增功能**，与移植解耦，可以按优先级慢慢做。
