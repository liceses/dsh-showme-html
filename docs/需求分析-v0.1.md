## 1. 事实勘察（已实测，不是猜测）

### 1.1 本仓库现状

- `D:\developing\DSH-plugin\showmeWithHTML\` **空目录**，无 `.git`、无 README、无任何需求文本。
- 因此"简单需求"目前只存在于**项目名**里。本文件是把这个名字展开成需求的一次尝试。

### 1.2 DSH 插件的标准形态（从你已有项目反推）

一个 DSH 插件 = 一个 npm 包，双半区：

| 半区 | 载体 | 职责 |
|---|---|---|
| Host（Node 进程） | `package.json` 的 `main` export | 注册模型工具、加 HTTP 路由、读写文件、访问 Session |
| Client（浏览器） | `package.json` 的 `exports["./client"]` + `dsh.client` 声明 | 注册 UI 槽位、渲染面板/卡片、调用宿主 |
| 装配 | `dsh.bundle.patch` → `cordis.patch.yml` 的 `insert` 行 | 告诉 profile 把这个包挂进插件栈 |

参考实现：`dsh-workspace-tree`（纯 JS，`lib/index.js` + `lib/client.js`）、`dsh-text-drop`（TypeScript + tsdown 构建，宿主路由 `/api/dsh-text-drop/save`）。
安装方式：`dsh plugin --profile web add link:<本地路径>`。**Client 半区热更新只在 `pnpm run dev:web` 同时运行时才免刷新**，其余改动需要重启/刷新。

### 1.3 DSH 已经有的 HTML 能力（决定了新插件的价值区间）

`@deepseek-ai/dsh-client-ui-sidebar-documentpreview` 已经提供：

- 右侧栏文档预览，**HTML 是一等公民**：以 `sandbox="allow-scripts"`（**不含** `allow-same-origin`）的 Blob iframe 贴边渲染；
- 相对依赖可用：直接声明的相对 `.js` / `.css` 会经宿主 `readRelated` 加载，上限单文件 4 MiB / 总计 32 MiB / 64 个资源；
- 文件大小受宿主 `maxFileBytes` 约束，超限直接失败而非截断；
- 渲染器本身是**可扩展注册表**：`ctx.documentPreviews.register({ id, extensions, priority, title, loading, wrap? })` + keyed 子槽 `sidebar.right.tab.document`；
- 还有更宽的 tab 类型注册：`ctx.sidebarRightTabs.register(...)`（kind、pattern、band、canOpen）。

### 1.4 因此真正的缺口是

| 现有能力 | 缺口 |
|---|---|
| 用户**点开文件** → 预览 HTML | agent **主动推送**某个 HTML 到用户眼前 |
| 手动"重新载入" | 文件变更后**自动刷新**（改一行 CSS 就得手点一次） |
| 内容身份 = 文件地址 | **临时内容**（不落盘、会话级、纯展示）无法表达 |
| 一次一个文件 | **多视图/画廊/并排对比** |
| 只读展示 | 用户在页面里的**交互结果回传给 agent** |

一句话：**现有的是"文件查看器"，缺的是"agent 的展示动作"**。这就是 `showmeWithHTML` 该站的位置。

### 1.5 可用的界面位置（本会话实测的可注册槽位）

来自客户端 Slot 实时目录（`cordis_inspect_query` → client/Slots）：

| 槽位 | 类型 | 用途 | 已被谁占 |
|---|---|---|---|
| `tool.call.toolview` | keyed（工具名） | 对话流里一张工具卡片 | 已被 read/write/bash/present/cordis_* 等 18 个工具占用，其余键自由 |
| `sidebar.right.pane.tab` | keyed | 右侧栏某个 tab 的正文 | 自由 |
| `sidebar.right.tab.document` | keyed（渲染器 id） | 文档预览正文（与 1.3 的注册表配套） | 自由 |
| `main` | keyed | **中央全局面板**（左侧图标进入，可整屏） | 目前只有 `conversation` |
| `sidebar.panellist` | list | 左侧栏的全局面板图标 | 自由 |
| `shell.overlay` | list | 框架级悬浮层（浮窗/画中画，不占布局） | 自由 |
| `settings.section` / `settings.general.item` | list | 设置页 / 单条偏好项 | 自由 |

**结论：四种展示位都是真实可用的**，不需要魔改 DSH。

## 2. 需求定位候选：把"showmeWithHTML"翻译成 5 种产品

| # | 一句话 | 触发方式 | 典型场景 | 主要成本 | 主要风险 |
|---|---|---|---|---|---|
| **P1** | **会说话的画布**：agent 用 HTML 讲解，而不是长篇 Markdown | 模型主动 / 用户说"用 HTML 讲" | 架构图、方案对比、时间线、状态机、数据表 | 每次生成 HTML 都烧 token | 内容质量不可控；可能为了好看牺牲准确 |
| **P2** | **即看视图**：agent 在做的页面/网站边改边给你看 | 文件保存后自动刷新 | 做网页、改样式、写报告 | 需要文件监听 + 刷新通道 | 与真实浏览器不一致；大页面性能 |
| **P3** | **可视化汇报**：每个回合/任务结束自动生成 HTML 总结页 | 回合结束自动 | "这轮干了什么、改了哪些文件、结果如何" | 自动化模板 + 额外推理 | 冗余噪音；用户可能更爱纯文本 |
| **P4** | **用 HTML 问你**：agent 给你几张可点的卡片让你选 | agent 需要用户决策 | 方案选型、验收确认、多选交互 | 回传链路（postMessage → 工具结果） | 与 `ask_user_question` 职责重叠，需要划清 |
| **P5** | **富展示器**：把长代码/diff/日志/表格渲染成好看的可折叠页面 | 命中特定工具结果 | 大 diff、长日志、性能数据 | 模板 + 数据提取 | 与现有代码卡片、侧栏预览重叠 |

> 我的判断：**P1 是灵魂，P2 是刚需，P3 是锦上添花，P4 与现有工具冲突需要谨慎，P5 容易变成重复建设。**
> 建议 **P1 做 MVP、P2 做第二个里程碑**，P3/P4/P5 明确列为"以后再说"。

## 3. 推荐需求定义 v0.1（待你确认后定稿）

> 下面按"P1 + P2"这一推荐定位写。如果你选了别的，这一节我重写。

### 3.1 一句话定位

> 给 agent 一个 **展示动作**：把一段 HTML（现场生成或来自工作区）推到你眼前，并能随着源改动自动刷新；你看完即可丢弃，也可留档。

### 3.2 用户故事

- **US-1**：当我要解释一件有结构的事（架构、流程、对比、数据），我希望 agent 直接给我一个页面而不是 300 行 Markdown。
- **US-2**：当 agent 正在写一个 HTML/网页产物，我希望不用自己去文件树里点、不用切浏览器就能看到它现在的样子。
- **US-3**：当 agent 改了这个产物的某一行，我希望视图自己更新，而不是让 agent 再"展示"一次。
- **US-4**：当我看到一张展示后，我希望知道它对应工作区里哪个文件（如果有），需要时能把它留住/打开/删掉。
- **US-5**：当展示内容很小时（一段 HTML 片段），我希望它不落盘、不污染工作区。

### 3.3 功能需求（FR）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-1 | 宿主注册模型工具 `show_html`，接受二选一的内容源：`html`（内联字符串）或 `path`（工作区文件，推荐用于长内容以省 token） | P0 |
| FR-2 | 可选参数：`title`、`height`、`mode`（`card` / `panel`）、`open`（是否自动展开）、`refresh`（`manual` / `watch`） | P0 |
| FR-3 | 客户端在对话内渲染该工具卡片：iframe 承载，沙箱不低于现有预览的安全基线 | P0 |
| FR-4 | 卡片提供：刷新、全屏/放大、在新面板打开、复制内容、查看源文件（有 path 时） | P0 |
| FR-5 | 内联内容写入会话级临时工件区（**不落工作区**），并可从 UI 侧再次打开 | P1 |
| FR-6 | `refresh: "watch"` 时，宿主监听该文件变更并通知前端自动重载 | P1 |
| FR-7 | 工具返回值对模型友好：只回传"已展示 + 尺寸/失败原因 + 工件 id"，**不回显 HTML 正文**（否则双倍烧 token） | P0 |
| FR-8 | 失败可诊断：文件不存在、超 `maxFileBytes`、依赖加载超限、沙箱拦截，都要说清楚 | P0 |
| FR-9 | 设置项：默认展示位、是否自动刷新、临时工件保留时长 | P2 |
| FR-10 | 交互回传：页面经 `postMessage` 把结构化结果交给卡片，再由卡片交给模型 | P2（若选 P4 则升 P0） |

### 3.4 非功能需求（NFR）

- **NFR-1 安全**：展示内容**永不**获得应用同源权限；不注入任何凭据/token；宿主路由需做路径校验，禁止越出工作区（除非显式允许）。
- **NFR-2 成本**：内联 HTML 走工具参数是 token 敏感操作，工具描述必须引导模型优先用 `path`；单次内联建议上限（如 64 KiB）并给出明确拒绝理由。
- **NFR-3 性能**：历史里多个 iframe 同时存活会卡；必须做"可见才挂载/离开即卸载"或静态占位。
- **NFR-4 一致**：展示的 HTML 与用户真实浏览器打开**可能有差异**（沙箱、无 cookie、无同源存储）；这一点必须在 UI 上如实说明，不能假装是"真实渲染"。
- **NFR-5 可卸载**：Ctrl/关闭后不留残留定时器、监听器、路由、iframe。

### 3.5 验收标准（AC，可测）

1. 在空会话里叫 agent「用 HTML 给我看看 XX」，**无需任何手动点击**，对话内出现可交互页面。
2. 同一能力用 `path` 指向一个 200 KB 的本地 HTML，能在 2 秒内渲染出首屏，且**工具调用参数里不含 HTML 正文**。
3. 修改该文件并保存后，`refresh: "watch"` 的卡片 **5 秒内自动更新**，无需重新对话。
4. 页面内 `localStorage`、`alert()`、表单提交、下载被沙箱拒绝时，卡片给出**人话解释**而不是白屏。
5. 展示 20 次后，会话滚动仍流畅（非可见卡片不持有活 iframe）。
6. 插件停用后，无残留路由、无残留 iframe、无控制台报错。

### 3.6 明确不做（Non-goals，v0.1）

- 不做通用浏览器（不做地址栏、不做标签页管理、不做书签）。
- 不替代 DevTools；不保证与真实浏览器像素级一致。
- 不自动把每个回合都变成 HTML（那是 P3，另开）。
- 不做远程 URL 抓取渲染（有 CORS/安全面，留到以后）。
- 不复刻右侧栏已有的"文件树里点开预览"能力（那是 DSH 自带的）。

## 4. 实现路径与利弊

| 路径 | 一句话 | 工作量 | 可回退性 | 适合 |
|---|---|---|---|---|
| **A** | 零代码探针 | 0 | 无需回退 | 先验证"有没有用" |
| **B** | 动态 Cordis 插件原型 | 小时级 | 一键 undefine | 先把 UX 看到手 |
| **C** | 正式插件：工具 + 对话卡片 | 1–2 天 | 卸插件即净 | MVP 落地 |
| **D** | 正式插件：常驻画布面板 | 3–5 天 | 同上 | 大画布/多视图 |
| **E** | 扩展既有文档预览注册表 | 1 天 | 同上 | 需求本质是"更好的预览器" |

### A. 零代码探针（**先做这个，成本为 0**）
- 做法：只用现有能力 —— `write` 写一个 `.html`，再用 `present` 声明交付物，用户在右侧栏点开预览。
- 优点：今天就能用；能立刻回答"我到底会不会看它"。
- 缺点：**没有"推送"**，全靠用户手动点；无自动刷新；沙箱与资源限额照旧。
- 结论：**建议在后天之前跑一次**。如果跑完你觉得"其实点一下也够"，那这个项目就该缩水甚至不做 —— 这是最省钱的结论。

### B. 动态 Cordis 插件原型（**建议的第一段真代码**）
- 做法：在当前 harness 里 `cordis_define` 一个 host+client 包，注册临时工具 + 用 `tool.view.cordis` 嵌入交互区域，直接在本会话看到效果。
- 优点：**分钟级**；免安装、免发版、免重启；UX 不满意就改，改完立刻看；不污染 profile。
- 缺点：**进程重启即消失**，不能分发，client 半区首次需你在 UI 里授权；能力受 Inspect 契约限制（能用的 Service/槽位以目录为准）。
- 结论：把它当"需求原型机"。**它回答的是"长什么样"，不是"能不能长期用"。**

### C. 正式插件：宿主工具 + 对话内卡片（**推荐 MVP**）
- 做法：
  - host：注册 `show_html` 工具；内联内容落到会话临时工件区；`path` 模式直接经 `dsh-host-webserver` 路由（形如 `/api/showme/<id>`）提供字节；`watch` 模式用文件监听 + SSE/长轮询推送变更版本号。
  - client：`tool.call.toolview` 以 `show_html` 为键注册卡片，iframe 指向路由，附刷新/全屏/查看源文件。
- 优点：与对话天然对齐，**历史可回看**；实现量最小；不需要新的导航/状态体系；失败面小。
- 缺点：卡片高度与滚动嵌套的体验上限一般；展示次数多了对话变长；生命周期跟着对话走。
- 风险：**token**（内联 HTML）与**iframe 数量**（性能）是两个真实的坑，靠 `path` 优先 + 非可见卸载化解。

### D. 正式插件：常驻画布面板（里程碑 2）
- 做法：注册 `main` 中央面板 + `sidebar.panellist` 图标（或右栏 tab 类型），维护"当前展示集合"。
- 优点：**最大画布**、可多视图/画廊/并排对比、可脱离对话流常驻、适合 P2 的"边做边看"。
- 缺点：要自己解决"展示什么/谁决定切换/何时清理"的状态问题；与既有右侧栏预览在功能上需要刻意分工；实现量最大。
- 硬问题：**host → client 的主动推送在现有架构里没有现成通道**（客户端→宿主有 RPC，反向要靠路由 + SSE 或客户端主动 watch）。这是 D 路径的主要技术风险，建议在 C 阶段就把"变更通知通道"设计好，D 直接复用。

### E. 扩展现有预览注册表
- 做法：`ctx.documentPreviews.register(...)` + `sidebar.right.tab.document` 注册一个 showme 渲染器，或 `ctx.sidebarRightTabs.register` 新 tab 类型。
- 优点：白拿现成的加载态、头部、重载、变更提示、会话作用域 store；与文件系统天然对齐。
- 缺点：注册表的内容身份是**文件地址**，临时/非文件内容表达别扭；交互模型仍是"用户打开"。
- 适合：如果最终结论是"我想要的其实是更好的 HTML 预览"，那这条最省事，而且应该**做成对 DSH 的贡献/扩展**而不是另起一套。

### 组合建议

```
A（今天，0 成本，验证真假需求）
  └─ B（本会话，小时级，定 UX）
       └─ C（1–2 天，MVP 可长期使用）
            └─ D（3–5 天，等 C 的变更通道验证后再上）
E 只在"定位被改写为预览器"时才走。
```

## 5. 硬约束与风险（提前认账）

| # | 约束/风险 | 具体表现 | 应对 |
|---|---|---|---|
| R1 | **沙箱语义** | `sandbox="allow-scripts"` 且无 `allow-same-origin` → 页面处于不透明源：`localStorage`/cookie 不可用；`alert`/`confirm` 需 `allow-modals`；表单提交需 `allow-forms`；下载需 `allow-downloads`；弹窗需 `allow-popups`；所有 `fetch` 都被视为跨域，需目标端 CORS。 | 明确"能展示什么/不能展示什么"，把拦截变成人话提示；确需放宽要逐项评估并单独决策 |
| R2 | **安全面** | agent 生成的 HTML 可以执行任意脚本、可向外部发请求（数据外泄面）；`path` 模式路由若校验不严可被用来读任意文件 | 永不注入同源权限与凭据；路由强制工作区根校验；默认不开放网络出站以外的额外能力 |
| R3 | **token 成本** | 内联 HTML 作为工具参数会让 token 翻倍甚至更多 | 工具描述强制引导 `path` 优先；内联设上限并给出拒绝理由；把常用页面做成模板/技能复用 |
| R4 | **渲染真实性** | iframe ≠ 用户真实浏览器（无 cookie/存储、可能被 CSP/沙箱影响） | UI 上如实标注；"预览我做好的网站"这类需求优先走本地 dev server 而非 iframe 重放 |
| R5 | **性能** | 长会话里多个活 iframe + WebGL/动画会显著掉帧 | 非可见即卸载/静态占位；单卡片尺寸上限；必要时手动"冻结" |
| R6 | **持久化与回看** | 临时内容在会话重开后是否还在？要不要进 git？ | 临时工件与会话绑定并设保留期；要留档就让 agent 显式写进工作区 |
| R7 | **与既有能力重叠** | 右侧栏已能预览 HTML 文件 | 差异化只在"主动推送 + 自动刷新 + 临时内容"三点上做，别重复实现文件浏览 |
