让 agent 把成果摊开给你看

长篇 Markdown 里没有「指认」，也没有「并排」。这个插件给 agent 一个展示动作， 给每样东西一个名字，把「我要这个」从一句描述变成一次点击。

四个痛点 下面每一条都能表态 —— 这页本身就是那个演示

点判定、写备注，③ 会自动把它组织成一行一条的文本。编号 pain-* 就是你可以直接引用的名字。

一次完整回路 五步，从「写完了」到「我知道你要哪个」

  1. 挑一套皮肤四套预设吃同一套语义标记，换皮肤一个字都不改标记。
  2. 写一页 HTML按共用标记组织内容：卡片、表格、时间线、证据图、结论条。
  3. 调一次工具show_html 只收路径不收正文——正文进参数会白烧一遍 token。
  4. 页面直接出现在对话里不用去文件树里翻，不用切浏览器；头部有刷新 / 全屏 / 浏览器打开。
  5. 点着回话页面替你写好一句话，一键追加进输入框，不覆盖你已经写了一半的草稿。

它是怎么送到的 一张图说清全部机制

关键取舍 页面里的相对引用之所以能用，是因为宿主按工作区目录结构镜像分发文件 （/api/showme/raw/<sessionId>/<路径>），而不是把文件读成 Blob。 代价是多一条路由，收益是 <img src="stills/a.png"> 这种写法照常可用， 而且同一个地址就是「在浏览器打开原文件」。

两句话的调用 agent 侧真正要做的只有这些

write({ path: ".dsh/showme/review.html", content: "<!doctype html>…" })

show_html({ path: ".dsh/showme/review.html",
            title: "设计评审",
            note: "挑一个变体" })
