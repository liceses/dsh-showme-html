# references/checklist — 交付前自检与常见错误

## 六问（每次 `show_html` 之前过一遍）

1. **`show_html` 的返回里有没有 `mermaid` / 缺图 / 结构 markdown 的报错？** 有就修，别绕。
2. **每个要用户点的东西都有可见 id 吗？** 页面上看得见、能复制。
3. **控件和对象同屏吗？** 不是"选项在顶上、内容在下面"。
4. **汇总文本一行一条吗？** `<id> <判定词>[：备注]`，判定词在页面上列出来了。
5. **每次变化都发消息了吗？** 不是只在"发送"按钮里发一次。
6. **窄屏（≈520px）能看吗？** 卡片里就是这个宽度。

## 这条页面到底该不该做

| 内容 | 用 HTML 吗 |
|---|---|
| 图 / 示意图 / 截图并排 | ✅ |
| 多变体挑选、逐项表态 | ✅ |
| 真表格、跨行状态 | ✅ |
| 长文讲解（>2–3 千字）、机制说明 | ⚠️ 用 `doc` 形状或直接 Markdown |
| 纯文字结论、短回复、普通问答 | ❌ Markdown 更快 |
| 纯代码 | ❌ 代码块 |
| 结论还没定 | ❌ 别为会变的东西写版式 |
| 一张图 | ❌ `read_image` |

判断标准一句话：**这件事用户是"读"更省事，还是"看"更省事。**

## 常见错误对照

| 症状 | 原因 |
|---|---|
| 页面显示「没找到数据文件」 | 数据文件与页面不同名（`foo.html` ↔ `foo.data.js`） |
| 报错里的文件名是一串 uuid | 这一页被**原生文档预览**打开了（blob iframe）。换卡片 / 侧栏 / 浏览器打开，或改静态引入 |
| 图片裂了 | 用了绝对路径 / URL；或页面在 blob 宿主里（相对图片必然裂） |
| 页面空白 | 没有 `window.SHOWME`，或 `.data.js` 语法错 → `node --check <文件>` |
| 判定点了没反应 | `core.js` 之后又写了脚本提前 return，或手写页面时自己 `wire()` 时早退 |
| 回执不更新 | 只在"发送"里 `postMessage`，没在判定变化时发 |
| `show_html` 直接失败、提到 markdown 结构 | 文本字段里写了表格/列表/引用/标题 → 换块类型，或 `plain: true` |
| `show_html` 直接失败、提到缺图 | `image` / `src` 的本地文件不存在 → 真的放进去 |
| `show_html` 直接失败、提到 mermaid | 图写错了 → 见 `mermaid.md` |
| 换皮肤没变 | 皮肤由数据里的 `skin` 决定；`<link>` 只是预设清单，四选一 |

## 别做的事

- 别把同一轮的多页摊开（先合并成一页）；
- 别为"排版好看"而做页面（Markdown 可搜索、可复制、可 diff）；
- 别改 `core.js` / `presets/*.css`；
- 别在页面里解释"这是因为沙箱"——卡片底部已经写了；
- 别让用户手抄回执（`postMessage` 是默认路径，不是加分项）。
